# VOC Analysis Framework — Detailed Chapter Guide

## Overview

This reference provides detailed instructions for each of the 10 core analysis chapters. Read this when executing Phase 3 of the VOC analysis workflow.

## Chapter 1: Executive Summary

**Purpose**: Give decision-makers the key takeaways in 60 seconds.

**Required outputs**:
- Core judgment (1-2 sentences capturing the market's defining characteristic)
- Top 3 product opportunities ranked by development value
- Top 3 risks/barriers ranked by severity
- Recommended entry strategy (bullet points, not paragraphs)

**Rules**:
- Write for a busy manager, not a data analyst
- Every claim must be traceable to specific data in later chapters
- If you can't identify clear winners, say so honestly — don't force ranking

## Chapter 2: Market Logic

**Purpose**: Understand WHY users buy in this category and HOW they choose between options.

**Analysis dimensions**:
- User purchasing motivations (need-based vs. impulse vs. replacement)
- Decision hierarchy: what matters most → least
- Price band logic: where do price-sensitive vs. premium buyers cluster
- Comparison behavior: what alternatives do users consider

**Output format**: Dimension comparison table (e.g., "Box Set vs. Roll Product" or "Budget vs. Premium") with columns for User Mindset, Purchase Reason, Pain Points, Profit Structure, and Development Insight.

## Chapter 3: Usage Scenarios

**Purpose**: Map WHERE and HOW the product is actually used.

**Extract from reviews**:
- Scenario mentions (e.g., "used this on my boat", "installed in my garage")
- Frequency estimation (count scenario mentions / total reviews)
- Common specifications per scenario
- User competency level (DIY novice vs. professional)

**Output**: Ranked scenario table with frequency %, typical specs, and product opportunity per scenario.

**Watch for**: Unexpected use cases that competitors miss — these are often the best opportunities.

## Chapter 4: Purchase Drivers

**Purpose**: Identify what ACTUALLY drives the buy decision (vs. what sellers think drives it).

**Analysis approach**:
1. Extract explicit preference statements ("I bought this because...")
2. Extract implicit drivers from positive review themes
3. Rank by mention frequency
4. Cross-reference with verified purchase reviews for higher confidence

**Output**: Prioritized driver table with Driver, User Motivation, and Development Recommendation.

**Key distinction**: Separate "checklist features" (must-haves that don't differentiate) from "conversion drivers" (features that tip the purchase decision).

## Chapter 5: Negative Review Analysis

**Purpose**: This is where product development happens. Find what's broken and fix it.

**Analysis approach**:
1. Cluster 1-2 star reviews by topic (use keyword co-occurrence)
2. For each cluster, extract representative user quotes
3. Assess: frequency (% of negative reviews), severity (return risk), solvability
4. Identify recurring patterns across multiple ASINs (industry-wide vs. individual product issues)

**Output**: Pain point table with columns: Problem, User Language (direct quote), Frequency, Severity, Solvable?, Solution Direction.

**Critical**: Separate "table stakes" problems (everyone has them, must solve to compete) from "differentiation" problems (few solve them, solving creates advantage).

## Chapter 6: Specification Matrix

**Purpose**: Quantify which specs, sizes, colors, and configurations users actually want.

**Extract from reviews**:
- Size mentions (count and sentiment per size)
- Length preferences (what users say about length)
- Color preferences (which colors get positive mentions)
- Bundle/kit preferences (what combinations users request)

**Output**: Recommended spec grid with Size, Length, Color, Priority, and Target User for each spec.

## Chapter 7: Competitor Structure

**Purpose**: Understand what top performers do differently from bottom performers.

**Analysis approach**:
- Compare high-BSR vs. low-BSR (or high-rating vs. low-rating) products
- Identify common traits of 4.5+ star products
- Identify common failure modes of sub-4.0 star products
- Note price-VOC relationship (do higher-priced products have better reviews?)

**Output**: Contrast table showing what winners do vs. what losers do, with actionable takeaways.

## Chapter 8: Opportunity Mining

**Purpose**: Translate VOC into concrete product development directions.

**Analysis approach**:
1. Cross-reference pain points + purchase drivers + scenario gaps
2. Identify underserved scenarios or specifications
3. Evaluate each opportunity by: market demand signal, competitive moat potential, implementation difficulty
4. Prioritize: quick wins first, strategic plays second, long-shots last

**Output**: Ranked opportunity list with development value, target user, and estimated difficulty.

## Chapter 9: Bundle Recommendation

**Purpose**: Recommend specific SKU combinations that maximize conversion and AOV.

**Design bundles by**:
- Scenario (e.g., Marine Kit, Automotive Kit)
- Skill level (e.g., Starter Kit, Pro Kit)
- Specification (e.g., Small Gauge Kit, Large Diameter Kit)

**For each bundle**: define positioning, configuration, materials, color, target price band, development value, and target keywords.

**Principle**: Bundles shouldn't just combine random sizes — they should solve a specific user scenario completely.

## Chapter 10: Listing Optimization

**Purpose**: Translate VOC insights into Amazon listing strategy.

**Output**:
- Hero image direction (what to show based on user priorities)
- Title keywords (high-frequency user language from reviews)
- A+ Content direction (what pain points to address visually)
- Bullet point themes (match user purchase drivers)
- Backend search terms (user language variations found in reviews)

**Rule**: Always use the EXACT language users use in reviews, not seller jargon.
