# weekly-ops-review

## 目标与边界

从整体经营、产品线、父ASIN、库存与评分定位经营问题，给出有数字依据的解释及“动作、时限、验收目标”。先定义问题，再解释可能原因；将已证实的变化与待核查的假设分开。

只读飞书并生成自包含中文 HTML。调整广告/价格、改写飞书记录、发货、创建在线文档、发送消息均不属于本 skill 的默认授权。

## 默认统计口径

以下为用户已确认的长期默认值；用户当次明确要求优先：

| 层级 | 默认范围 |
|---|---|
| 整体指标、整体六项成本、近3周经营趋势 | 全部有经营数据的产品，含“卖”和“不卖” |
| 产品线汇总、父ASIN明细、异常、成本诊断与优化动作 | 仅 `卖/不卖 = 卖` 的子体 |
| 库存健康、评分变化 | 仅在售子体；低库存再要求本周销量 > 0 |

- “有经营数据”指销售、利润、订单、销量、访客、广告、费用、退货或库存等至少一项有效非零；仅有品名、排名、评分等元数据不构成经营数据。停卖但有费用或亏损、无销售的记录也必须纳入整体。
- 每周独立筛选，勿将本周产品名单强行套在历史周；整体与在售两种口径使用独立数据集。整体与产品线合计之间的差额可来自停卖产品，不强行凑齐。
- 状态缺失的记录若有经营数据，计入整体但不默认为在售；影响解释放在页尾。
- 默认不读取对标竞品表，不展示竞品模块、表不存在/不可用等说明；不要以无证据的竞品降价或价格战解释变化。旧版竞品参考和脚本不属于当前默认流程。
- 广告 CTR 仅在有有效曝光量与点击量时计算；缺曝光时直接省略整张报告里的 CTR 卡片、列、段落和解释，不显示“CTR 无数据”。
- 数据口径与来源放页尾，首页直接进入经营结果；关键指标确实缺失且影响交付时如实说明，不编造或用零填补。

## 工作流程

### 1. 确定周期与存储位置

- 使用用户时区确定周一至周日。明确给了日期就直接执行；仅给月日时据当前年份及周日期验证年份。
- “上周”取最近完成的一周，“本周”取所在周并说明尚未完成；未给日期默认最近完整周。先在进度中说明采用周期，无实质歧义不额外等待确认。
- 读取目标周、上周和再前两周，用于环比及连续趋势；主页面默认展示近3周。
- 报告默认路径：`D:\CodexProjects\weekly-ops-review\ops-reports\{start_date}_to_{end_date}_ops_review.html`。如用户指定位置则遵从；不在旧 C 盘项目默认新增文件。
- 更新同周报告前保留可恢复旧版；校验通过后再替换。遵循实际文件写权限，不能因改存储盘绕过批准。

### 2. 读取数据

Base：`FHxDbhbQKaIwrHsuNr3cUBXgn4d`。

- 主表：周复盘 `tbl2l56CZpF0y1l1`。
- 超龄库存：`tblsMqzOk1fhNLh2`。
- 仅需回退时读取：源数据-周 `tblFaBRW7fQKeMV0`、利润源数据 `tblv5QHS4ViFamBh`；产品元数据不足再查“信息”。
- 优先用已配置的飞书 MCP，只调用查询操作。按 `年 + 周` 筛选并在客户端复核 `周日期`，处理跨年周，避免混入同名历史周。
- 每个查询按响应返回的 `page_token/pageToken` 持续分页直到 `has_more/hasMore` 为假，不推算下一游标。独立周和库存可并行读取。
- 不假定每周50条或库存固定条数；近期每周约270条，仅作合理性参考。核对接口总数、实际取回数及唯一记录数，目标周少于10条时先排查查询范围。
- 超过5个产品缺少销售、利润或广告等关键 lookup 字段时，按日期和ASIN回退源表；关键缺失集中在亏损/高销售对象时也要回查。保留缺失状态，不填作0。
- 若 MCP 鉴权失败，可用已有飞书凭证请求官方只读 API，路径和注意事项见数据源参考。凭证和令牌不得进入输出、脚本或报告。

### 3. 规范化与汇总

- 解包 lookup 的 `value` 数组及富文本的 `text`；保留0与空值的区别。多个 lookup 值不可静默取第一个，先排查重复匹配。
- 主键为实际周起始日期 + ASIN；重复记录先核验，避免双算。每周按上一节范围分别建立整体、在售数据集。
- 金额、订单、销量、点击等先求和，再计算毛利率、广花比、CPC、CVR、ACOS等；不要平均子体百分比。
- 父ASIN缺失时暂以子ASIN为单独分析单位并标注；不同类目排名不可混加或平均。
- 成本方向、负利润环比、评分零值、低库存和代表子体排名使用指标规则中的确定口径。
- 核对重算的销售额环比与飞书公式；不一致时优先经过核验的原始两周数据，页尾简短说明影响。

### 4. 分析经营问题

- 整体：销售、利润、毛利率、广告与广花比、访客→订单→客单价、六项费用及近3周趋势。
- 产品线与父体：在售规模、利润、投放效率；核对销量款/利润款/精品利润款的定位、生命周期、实际及目标排名。
- 按规则识别父体核心异常和辅助信号，分析费用中变动最大的项目及流量、转化、库存、评分的证据链。
- “同期发生”不等于“已证实原因”：仓储费上涨应核对计费期间；排名变化应核查流量；退款应查订单与原因；产品线一起下跌并不能直接证明市场萎缩。
- 同一父体的问题、成本和动作汇总为一张卡片；优先级考虑严重程度、利润/销售绝对影响和可逆性。
- 动作对准该父体证据，每项包含做什么、时限、验收指标/触发条件。建议目标不是必然预测，不保证降本或排名恢复。
- 不默认输出主观4维打分或机械两周外推；用户明确要求预测时披露假设。

### 5. 生成与验证

使用模板的五板块：**整体经营 → 产品线 → 经营问题与优化 → 库存健康 → 评分变化**。

- 结果优先，信息按需展开；六项整体成本、趋势、父体明细及长库存表默认折叠。
- 问题卡片集中展示异常指标、流量转化、成本结构、风险定位及动作验收；不再另建重复的“利润专项分析”或“下一步动作建议”大板块。
- 页尾说明来源、范围、阈值、缺失或计算限制；不前置数据可用性说明。
- 检查目标周/上周分页完成、整体含停卖、在售异常未混入停卖。核对全部红色问题与原始记录。
- 检查负利润增亏/减亏方向、成本上升/下降方向、排名绿色“上升 +N 位”/红色“下降 -N 位”、评分有效值和0.1边界。
- 确保每张异常父体卡片都有成本对比和“动作/时间/验收”，成本不可得时如实写“待核对”；正常父体低于毛利红线时标“毛利率红线”，不要仅用绿色“正常”覆盖风险。
- 缺曝光时整个成品省略 CTR；成品不出现竞品表相关文字；没有被省略指标的占位卡。
- 检查UTF-8、无外部依赖、折叠可用、长表未截断；可用时检查1280px及390px布局，避免页面整体横向溢出。
- 最后交付报告绝对路径链接和少量关键结论，不在聊天重复报告正文。

## 调用示例

`$weekly-ops-review 分析11-09~11-15周复盘`

确定对应周 → 读取完整分页 → 整体含停卖、在售分层 → 同父体合并诊断与动作 → 输出五板块 HTML。
