# Output Patterns

## Fixed Table

Use this column order unless the user explicitly asks for another format:

| 图片 | 目的 | VOC痛点 | 用户需求 | 画面 | 文案 |
| --- | --- | --- | --- | --- | --- |

## Default Sequencing Logic

### Main image

Use the main image to reduce identity confusion.

Show:
- exact product form
- current variation cues such as color, size, count, or length
- only the items included

Avoid:
- crowded scenes
- unrelated accessories
- multi-claim copy blocks

### Image 2

Use Image 2 to prove the most important result.

Good patterns:
- before vs after
- cross-section
- close-up outcome
- mechanism that explains why the result is believable

### Image 3

Use Image 3 to remove the biggest selection risk.

Good patterns:
- size chart
- fit guide
- compatibility table
- included-items breakdown

### Image 4

Use Image 4 to prove the strongest high-value scene.

Good patterns:
- harsh environment use
- high-stakes use case
- trust-building finished application

### Image 5

Use Image 5 to reduce setup friction.

Good patterns:
- 3-step process
- tool recommendation
- quick how-to
- wrong-vs-right usage cue

### Image 6

Use Image 6 to clarify best-fit use cases or boundaries.

Good patterns:
- best for / not ideal for
- scenario matrix
- use-case gallery with labels

### Image 7

Use Image 7 to close quantity, storage, or finish-quality doubts.

Good patterns:
- package contents
- storage convenience
- organized layout
- product finish or quality close-ups

## How To Fill Each Column

### `目的`

Write the conversion job of the image in one sentence.

Examples:
- Clarify this is a roll product, not a kit
- Prove the sealed result after shrinking
- Make size selection fast

### `VOC痛点`

Write the buyer fear or complaint the image must resolve.

Examples:
- Worried there is no adhesive
- Unsure which size to buy
- Afraid it will not survive wet conditions

### `用户需求`

Translate the pain point into a desired outcome.

Examples:
- Finish the repair once without rework
- Confirm fit before ordering
- Trust it in outdoor use

### `画面`

Describe what should be visibly shown.

Prefer:
- exact objects
- comparison structure
- labels or callouts
- specific scene choice

Avoid:
- generic phrases like "show premium feeling"

### `文案`

Keep it short and image-ready.

Prefer:
- one headline
- optionally one supporting phrase

## Adaptation Rules

- If the product has heavy compatibility risk, move compatibility earlier.
- If the product is highly visual and low-friction, spend more space on scenario proof.
- If the product has many variations, make variation identification explicit in the main image and Image 3.
- If VOC shows repeated misuse, dedicate one image to boundaries even if it feels negative; preventing the wrong order is often more valuable than broadening appeal.
