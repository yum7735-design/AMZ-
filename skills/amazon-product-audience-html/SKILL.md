# Amazon 产品 × 人群画像分析

将“产品是什么”与“谁在购买”合并分析，回答产品实际吸引的人群、产品—人群—价格—卖点匹配度，以及可验证的人群沟通机会。

## 输入与范围

需要尽可能取得以下两类数据：

- 产品事实：ASIN/父 ASIN、变体、品牌、标题、五点、价格、评分、评论数、类目、图片或 A+。
- 人口统计：细分名称、维度（年龄/性别/收入/教育/家庭结构等）、买家数、买家总数、订购件数、订单总件数、占比、报告日期和变化值。

用户指定飞书多维表格时，先只读方式确认：

1. 产品 Listing 表、人口统计表及字段 schema；
2. 父 ASIN 下的所有变体；
3. 统计是占比、指数、渗透率还是其他口径；
4. 人口统计数据覆盖了哪些变体、报告日期是什么。

不得回写飞书，除非用户明确授权写入。

## 关键口径规则

- 不把“某人口细分在买家中的占比”写成美国总体人口渗透率。
- 父体存在多个变体时，先披露人口统计覆盖范围。若多个变体的买家数相加，必须称为“变体报表数值加总”，不能称“父体去重独立买家”。
- 不同人口维度各自的分母可能不同；每个维度单独核对买家总数与细分合计。
- Information Not Available / 未披露必须单列。可同时展示：
  - 总买家占比：细分买家数 ÷ 该变体或覆盖变体买家总数；
  - 已知样本内占比：细分买家数 ÷ 排除未披露后的该维度买家数。
- 只有在分母一致且记录可加总时，才聚合多个变体；必要时用买家数/订购件数重新计算加权占比，禁止平均各变体百分比。
- 原始数据与计算后的汇总均要保留，便于审计。

## 证据分层

所有结论都要明确归入以下之一：

- 【数据事实】：直接来自产品字段或人口统计数值。
- 【合理推测】：产品特征与人群结构之间的合理解释，不能伪装成事实。
- 【待验证假设】：需要 VOC、搜索词、竞品价格、广告转化、A/B 测试或更完整数据确认。

禁止：

- 因男性占比高就称为“男性产品”；
- 因高收入占比高就判断“可以涨价”；
- 因学历高就判断为“专业用户”；
- 因 Listing 写了某应用就断言买家都在该场景使用；
- 在缺乏竞品、转化或价格弹性时给出具体价格升级结论。

## 分析框架

先独立完成产品识别，再解读人口统计，最后做匹配分析。

### 产品识别

提取产品类型、核心用途、卖点、使用复杂度、价格带与变体差异。Listing 的功能/性能文案只能写作“页面主张”，不是验证后的产品能力。

### 人口统计

每个可用维度至少输出：

- 年龄：单一最高段、Top 2、已知样本中的集中度。
- 性别：已知样本内结构；明确“偏高”不等于排他。
- 收入：核心区间、分布广度、与当前价的匹配边界。
- 教育：结构和对信息表达清晰度的启示；不等于专业性。
- 婚姻/家庭结构：只有未披露比例可接受时才作为画像支撑；否则明确为弱线索。

### 产品 × 人群

建立产品特征、人群特征、匹配度、事实依据和商业含义的矩阵。区分：

- 强匹配：有明确数据且产品逻辑相符；
- 弱匹配：产品理论适合，但数据支持不足；
- 意外人群：与直觉定位不同的真实结构；
- 潜在人群：有一定规模或产品逻辑，但必须标为待验证。

输出 3 个 Persona：核心人群、次核心人群、潜在人群。Persona 只能是工作假设，不得虚构职业、家庭状态或具体使用场景。

## 交付物

默认输出一个独立、中文、离线可打开的 HTML 报告，并单独导出原始人口统计 CSV，避免把几十条明细堆在报告正文。

HTML 建议包含：

1. 执行摘要与数据范围警示；
2. 产品基础事实和变体覆盖；
3. 年龄、性别、收入、教育等统计表；
4. 产品 × 人群匹配；
5. 三类 Persona；
6. 人群 × 卖点、决策链和机会；
7. 数据来源、口径和限制；
8. 指向原始 CSV 的下载链接。

正文应以汇总和结论为主；完整原始记录写入独立 CSV。CSV 至少包含 ASIN、变体、人口统计类型、人口统计细分、买家数/总数/占比、订购件数/总数/占比、变化值和报告日期（如有）。

报告中给出一个简短的管理层结论表和一句话画像，并说明每个关键判断的证据等级。

## 验证

交付前至少检查：

- HTML 和 CSV 都已生成，CSV 行数等于导出的原始记录数；
- HTML 内关键数字可追溯到汇总计算；
- 百分比显示、分母、覆盖变体、未披露比例一致；
- 所有“推测”与“待验证”已显式标识；
- 不包含未授权的外部写入。
